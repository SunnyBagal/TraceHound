## Failure modes (from the transcripts)

None of the 6 failed runs made a successful edit.

- **`bun run -e "…"` (runs 2, 6, 7, 8).** `bun run` doesn't take `-e`; it prints its usage text
  (about 1,900 tokens) with exit code 0. The model kept sending variations. In runs 6–8 the
  repeated usage dumps grew the context until the 300k token limit. agent-v2's prompt mentions
  both `bun run <file.ts>` and `bun -e '<code>'`; whether that invited the mash-up is unverified.
- **Refusals ignored (run 2, and briefly 6–8).** The repeat guard refused the same call 31 times
  in a row in run 2; the model re-sent it every turn until the step limit.
- **Near-duplicate search loops (runs 3, 4).** About 30 slightly different greps over `tests/`
  for "10%", "200", "190", "180" after the buggy line had already been read. Not identical, so
  the guard doesn't apply. Run 4 found the bug at call 39; its edit was call 41 and never ran.
- **Still present from v1:** invented tools on the first turn (`explore`, `str_replace_editor`),
  an edit to a nonexistent `calculateDiscount` before reading the file (run 3), and `write_file`
  on an existing file (run 4).
