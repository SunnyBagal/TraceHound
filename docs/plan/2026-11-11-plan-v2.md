**Found while writing v2 (checked against code; each changes a task):**
- **F-a. One repository per runner invocation.** `scripts/run-tracehound.ts:215` (on main) refuses a run whose cases have more
  than one `repo`. v1's "4 batches of 10" and the caps check's 10/10/10/10 and 10/10/9 layouts cannot run as written.
  Batches are per repository (§6). The rolling batch rule of 076a works unchanged with per-repo batches.
- **F-b. Case order is manifest order.** `--ids` only filters (`run-tracehound.ts:212`). "The same PR order for every
  tool" (S0.4) therefore means manifest order inside each repository, in a fixed repository order.
- **F-c. The runner's defaults are not the protocol's.** Defaults: case cap $0.25 (`run-tracehound.ts:135`), fixes and
  contracts from the Action's defaults. Every command passes `--fixes off --contracts off --cache off
  --max-usd-per-case 0.40` explicitly.
- **F-d. `--cache off` stops reads, not writes** (`packages/analyzer/src/llm/cache.ts:6-8`). So R1's replies are in the
  cache afterwards, which is what makes "R2 as a cache replay" (cut order) possible with `--cache read`.
- **F-e. L3 step 1 is already done** by B3: references reach the model in 13 of 42 chunks today and 36 of 42 with the
  10,000-character reserve, and the reserve drops the labelled lines of 4 bug cases from the context block
  (`run/out/bunny.audits.md` (c)). Step 2 is cut, so E1 only reports these numbers.
- **F-f. CodeRabbit's allowance can shrink with use.** Its paid plans lower the hourly refill rate as reviews in the
  last 7 days grow (https://docs.coderabbit.ai/management/rate-limits, "How the allowance refills"); the page does not
  say whether the OSS allowance does the same. P1's ≈ 40 dev reviews may fall inside the 7 days before H1. So a rate
  measured in P1 is an upper bound for H1 **(estimate)**; the H1 runbook is written at 1 per hour.
- **F-g. Re-trigger collision at 1 per hour.** With 29 first triggers one hour apart (hours 0–28) and a re-trigger "24 h
  after that PR's own trigger" (076a §13.6), a re-trigger for PRs 1–5 falls in the same hour as the first trigger of PRs
  25–29. At an allowance of 1 per hour the second request is rate-limited. **Needs a ruling (R-1)**; see §8.
- **F-h. A rate-limited CodeRabbit request posts a comment and runs no review**; "the comment is the authoritative
  signal that no review ran" (same URL, "What happens when a review is rate-limited"). The collector and the runbooks
  treat that comment as "no review ran", never as a completed zero.
- **F-i. B3's chunk count lowers the cost estimate.** 40 dev cases give 42 chunks (old dev: 48), so a dev run is
  ≈ $2.61 by chunk scaling against ≈ $3.73 by the +25% basis (`run/out/bunny.audits.md` (a)); both are estimates. The
  caps keep the higher basis.

## 2. Metric and claim (corrections 1, 2, 6; rulings S0.3, 076a §13)
- **Headline:** bugs caught of 20 held-out bugs with a Wilson 95% interval (no continuity correction), comments per PR,
  cost per PR. F appears on dev only.
- **Comparison:** exact two-sided sign test on discordant bugs, α = 0.05 (076a §13.1). 6 net bugs is the smallest
  observed gap that can reject, and only as 6–0; 8–1 and 10–2 also reject, 5–0 (p = 0.0625) and 7–1 (p = 0.0703) do not
  (`run/out/bunny.plan-audit.md` §2).
- **Power, stated honestly:** under independent catches a true 30-point gap (20% vs 50%) is detected with probability
  0.37; about 35 points are needed for 0.5 and about 48 for 0.8. Positive correlation between the tools' catches raises
  this (0.44 at φ = 0.2, 0.53 at φ = 0.4); the correlation is unmeasured (`bunny.plan-audit.md` §3).
- **If the test does not reject:** the sentence is "no detectable difference at this sample size". Never "catches as
  many", "matches", a rank, or equivalence.
- **Cost:** "$0.075 per PR measured on non-TypeScript PRs" (`docs/budget.md` "Unit costs") until R1 gives a TS figure; then R1's
  and H1's ledger figures replace it.
- **Counted comments:** top-level line-level review comments from the tool's own bot account; replies, summaries,
  walkthroughs, review bodies and issue comments are excluded (the rule of `packages/analyzer/src/bench/convert.ts`,
  audit C015). TraceHound is scored from its local export, capped at 15 model findings.
- **Scope of the claim:** the repositories with at least one held-out case, with per-repo counts filled by codex (076a
  §13.8).
- **Not claimable from this run:** true precision (label matches are a lower bound), recall of all bugs, anything
  about Augment, Cursor or Copilot, other languages.

Rules that go with the table (076a "Caps"):
1. **Rolling batch rule.** For every runner batch: `--max-usd-run` = job cap − job spend so far (ledger delta since the
   job's first call, including reruns). A case the runner did not start (exit 3) is added to the next batch of the same
   repository.
2. **Judge-only jobs** (L1, L4, H2, and S1's judging): every process runs with `TRACEHOUND_BUDGET_RUN_USD` = job cap and
   `TRACEHOUND_BUDGET_TOTAL_USD` = ledger total at job start + job cap. Without these the only cap is the $1 default
   (`packages/analyzer/src/llm/budget.ts:10`).
3. **077 recompute.** After R1, R2's and H1's caps are recomputed once by the caps-check method
   (`run/out/bunny.caps-check.md` §4.2) from R1's measured per-case costs, at 95% completion, and written into decision
   077 before R2's first call. Money comes from the $1.18 only, H1 first. If R2 cannot reach 95% it runs at what fits
   and reports the missing cases.
4. **Re-plan** if console ÷ ledger is above **1.08** at any check. Cut order: L2, then R2 becomes a cache replay of run
   1 (reported as "fresh-draw confirmation NOT RUN"). H1, H2 and the reserve are never cut.
5. **L2 above 11 failed chunks:** redraw the first 11 by case id, then chunk index; the gate applies to those.
6. Paid jobs run one at a time: the ledger is shared, and another process's calls count against a running job
   (`bunny.caps-check.md` "Limits").

## 4. The tie rule (correction 4)
A margin under 3 cases is a tie and **A0 stays**. If several arms pass a gate, the cheaper measured arm wins; at equal
cost A0 first, and between A1 and A2 the one with fewer comments per case (076a §13.2). This replaces both v1's wording
and "the simpler arm wins".
