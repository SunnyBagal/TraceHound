For artu1 (runs it), codex (GO before, arithmetic after). Planner A, 2026-11-11.
Plan: [`plan-v2`](../plan/2026-11-11-plan-v2.md) §3, §5, §6. Budget lines: **R2, cap $4.15 until decision 077 recomputes
it**; **L4 $0.10** (not needed, see §4). Depends on decision 077 pushed, and on codex GO for any code that 077 adopted
(the third attempt, `docs/specs/E1.md` §2.4).

R2 answers two questions: does the candidate hold up on a second draw (the non-regression gate), and what does the
exact held-out command cost and how long does it take. It selects nothing new.

```sh
TH=~/Projects/TraceHound; TS=~/Projects/tracehound-testset; RUNS=~/Projects/tracehound-runs
```

## 0. Preconditions
1. Decision 077 is on `main` with: the candidate arm, attempts 2 or 3, K (that arm's judged catches in run 1), R2's and
   H1's caps (`docs/specs/E1.md` §6).
2. `git status` is clean and `HEAD` is the commit 077 names. If the third attempt was adopted, it is merged with codex GO
   and `pnpm test`, `pnpm typecheck` are green on that commit.
3. R1's console check passed (ratio ≤ 1.08). No other paid process runs.
4. The cut order has not turned R2 into a replay (plan-v2 §3 rule 4). If it has, go to §5.

## 1. Batches
The same five batches, in the same order, as R1 (`$R1/job.md`): medusa 8 + 8, payload 9, twenty 8 + 7.

## 2. One batch (identical to R1 §2 except `$J` and `$CAP`)
```sh
L0=$(ledger); echo "L0=$L0 $(date -u +%FT%TZ)" >> $J/job.md          # once
RUNCAP=$(echo "$CAP - ($(ledger) - $L0)" | bc)                        # every batch
cd $TH && node scripts/run-tracehound.ts --manifest $TS/cases/dev/manifest.json --clone $TS/repos/$R --ids $IDS \
  --out-dir $J/th --fixes off --contracts off --cache off --max-usd-per-case 0.40 --max-usd-run $RUNCAP    # dry run, then --execute
```
This is the held-out command shape: only the manifest, the clone, the ids and the out-dir differ in H1. The rules for
exit codes, unstarted ids (rolled into the next batch of the same repository) and the single rerun of a `failed` or
`cap` case are R1 §2's, unchanged. `--cache off` matters here: with reads on, R2 would return R1's replies
(`packages/analyzer/src/llm/cache.ts:6-8`) and would not be a fresh draw.

## 3. After the last batch
1. `mkdir $J/official` and copy each case's official record (R1 §3 step 1); `node scripts/testset/replay-arms.ts --records $J/official --out $J/arms` → exit 0.
2. Judge the candidate arm only, with R1's goldens:
   `SPENT=$(echo "$(ledger) - $L0" | bc); TRACEHOUND_BUDGET_RUN_USD=$(echo "$CAP - $SPENT" | bc) TRACEHOUND_BUDGET_TOTAL_USD=$(echo "$L0 + $CAP" | bc) node packages/analyzer/src/bin.ts bench score --golden $R1/goldens/bench-golden.json --reviews $J/arms/$ARM --detail $J/judge/cand.v1.json --concurrency 1`

3. `node scripts/testset/location-hit.ts --side dev --goldens $R1/goldens/goldens.json --tool cand=$J/arms/$ARM --out $J/location.json`
4. `node scripts/testset/score-testset.ts --side dev --goldens $R1/goldens/goldens.json --policy $POLICY --tool cand=$J/arms/$ARM --judge cand=$J/judge/cand.v1.json --records cand=$J/th --out $J/summary.json`
5. Console check ≥ 2 hours after the last batch; ratio ≤ 1.08.

**The gate (decision 076 R2, verbatim in substance):** C2 = the candidate's judged catches of 31 in run 2; K = the same
arm's judged catches in run 1 (written in 077).
- **C2 ≥ K − 2 → PASS.** The candidate goes to the freeze.
- **C2 < K − 2 → FAIL.** "Revert to the run 1 incumbent and say so": the frozen configuration is **A0 with 2 attempts**
  (what run 1 executed). If the third attempt had been merged, bunny reverts that merge with a revert commit, codex
  confirms `pool-verify-identity.test.ts` is green with no snapshot change, and F1 tags the reverted commit. No third run
  decides it.
- If fewer than 40 cases ran (cap), the gate is applied to the cases that have an official record in **both** runs: K
  and C2 are both recounted on that common set, and the report says how many cases that is.
- Report beside the verdict: the error range (≈ 12–26% false reject of an equal candidate; estimate).

## 4. L4: union of runs 1 and 2 (report only; $0)
No judge call is needed. For the candidate arm, from the two judge details already paid for:
- union catches = cases caught in run 1 **or** run 2; also the counts caught only in run 1, only in run 2, in both;
- comments per case = run 1's + run 2's (an upper bound: duplicates are not removed);
- cost per case = run 1's + run 2's.
State it as "a second draw would add U − C1 bugs at twice the cost and up to twice the comments". It is **not
adoptable** (decision 076 L4): there is no budget for a confirming run. The $0.10 line stays unspent.

## 5. If R2 was cut to a cache replay
Run §2 with `--cache read` instead of `--cache off`, under the same rolling cap. Requests unchanged from run 1 are
answered from the cache; a changed request (a third attempt, if adopted) and **any cache miss** are paid calls: the
client only refuses to call in its `offline` mode (`TokenFactoryClient` in `packages/analyzer/src/llm/client.ts`), and
the runner has no flag for it (codex's plan-v2 audit, "adjacent execution caveat").
- After the **first** batch, read its ledger delta per case. A replay on old dev cost ≈ $0.0073 per PR (`docs/budget.md`
  "Unit costs", 073r). If the delta is above **$0.03 per case**, the cache does not cover run 1: stop, do not run the
  other batches, report "cache coverage incomplete" with the number. ($0.03 is Planner A's threshold: four times the
  073r figure and under half of a fresh case; artu1 may replace it in 077.)
- Then §3 steps 1–4. The gate is **not applied**; the report says "fresh-draw confirmation NOT RUN" (ts-protocol §5),
  gives the live spend and the number of live calls, and F1's predictions say the same.

## 8. The three most likely ways to get this wrong
1. **Comparing different arms or different case sets.** K and C2 are the same arm, judged by the same judge, on the
   same cases. Comparing run 2's candidate with run 1's A0, or 40 cases with 37, makes the gate meaningless.
2. **Running from the wrong commit.** R2 must run the code that F1 will tag (077's commit, third attempt in or out). A
   run from an older checkout confirms a configuration that will not be frozen.
3. **Treating a FAIL as a reason to look again.** The rule after a FAIL is fixed: A0 with 2 attempts. A "tie-break"
   run 3 does not exist in the budget and would be selection on noise (the gate's false-reject rate is already 12–26%).
