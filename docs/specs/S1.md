## 3. What S1 must write down (in `run/out/artu1.smoke.md`, counts and logins only)
- The case id, its repo, its diff size, the PR number.
- TraceHound: status, findings, posted comments, chunks ok and failed, ledger delta, wall time.
- Per tool: minutes from trigger to first inline comment; login and type of the comment author; whether a review object
  exists; number of inline comments, of issue comments, and whether the request cost a Greptile credit (dashboard
  before and after).
- CodeRabbit's reply to `@coderabbitai configuration`: whether any setting came from a repository file (expected: none
  for medusa and twenty).
- Whether CodeRabbit's messages show a remaining hourly allowance, and the number
  (https://docs.coderabbit.ai/management/rate-limits says it "can show … the number of included reviews that remain").
- The ratio of step 16, with both readings and their UTC times.
- **Per tool, one line (premortem gap G1):** "zero-inline completion seen: yes / no; the object that marks it". S1
  reviews one bug case, so the usual answer is "no (the review had inline comments)". Then the line also says what a
  review *without* inline comments would leave behind as far as S1 can tell: whether the tool submitted a review object
  at all (`pulls/N/reviews`), and which issue comments it posted (`issues/N/comments`: walkthrough, summary, "no
  issues" text). The collector calls a case completed only on a review object or a counted inline comment and never
  reads issue comments (`collectCase` in `scripts/testset/collect-tool-reviews.ts`), so a tool that marks an empty
  review with an issue comment alone would be read as `no-review`.
- Every command that refused or printed something unexpected.

## 5. The three most likely ways to get this wrong
1. **Running the runner with its defaults.** Without `--fixes off --contracts off --max-usd-per-case 0.40` the run is a
   different configuration (fixes on costs 3 more calls; the default case cap is $0.25,
   `scripts/run-tracehound.ts:135`). Read the dry-run plan line before `--execute`.
2. **Reading the console too early.** A reading minutes after the job misses it (`docs/budget.md` rule 5). The ratio is
   only valid ≥ 2 hours after step 4.
3. **Writing the login list from documentation.** `tools.json` comes from step 6's API output. A wrong login makes the
   collector count zero comments and call the case `no-review`, which looks like a tool failure.
