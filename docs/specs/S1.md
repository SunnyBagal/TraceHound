review object, inline comment or issue comment on the PR after the trigger, except a rate-limit or error message.

completed review either; such messages go into the tool's `notCompletion` list beside the rate-limit and error
messages, and S1 records their **exact text**. Issue
comments are read for completion only; counted comments stay inline only. S1 is where both tools are first seen doing
this, and the only place Greptile is seen before the held-out window.

## 5. The three most likely ways to get this wrong
1. **Running the runner with its defaults.** Without `--fixes off --contracts off --max-usd-per-case 0.40` the run is a
   different configuration (fixes on costs 3 more calls; the default case cap is $0.25,
   `scripts/run-tracehound.ts:135`). Read the dry-run plan line before `--execute`.
2. **Reading the console too early.** A reading minutes after the job misses it (`docs/budget.md` rule 5). The ratio is
   only valid ≥ 2 hours after S1's last paid call. Since 2026-11-13 it is also the only spend guard before R1.
3. **Writing the login list or a pattern from documentation.** `tools.json` comes from step 6's API output. A wrong
   login makes the collector count zero comments and call the case `no-review`, which looks like a tool failure; a
   `notCompletion` pattern that is too wide turns a real review into `no-review`, and one that is missing turns a
   rate-limit message or an "in progress" placeholder into a completed review with zero comments. A placeholder read
   only at 60 minutes may already be edited into the final comment: its text is saved at the early readings or not at
   all.
