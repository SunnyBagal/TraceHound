### Three cheapest implementation cuts to evaluate, with bounded dollar estimates
These already exist as switches, require no dependency/model/provider change, and have no measured savings yet. Dollar effects below use repository prices; they are **estimates/ceilings**, not measured per-PR gains. Let I/O be avoided input/output tokens; savings = `0.30 I/1e6 +0.90 O/1e6`.
| Cut | Estimated dollar effect | Quality tradeoff / next measurement |
|---|---|---|
| Turn optional fixes off for cost-sensitive use | Saves actual `action-fix` ledger cost, **not measured** in dev pipeline tables. Per omitted call: up to $0.0036864 completion cost + input; up to two calls/finding, hence $0.0073728 output ceiling/finding | Removes suggestions, retains review findings (`action.ts:310–317`). Attribute live `action-fix` cost by PR; no claim this lowers the quoted $0.0626 benchmark median |
| Enable existing lenient parser experimentally | Avoided retry saves up to $0.0288 output + input per generator call. Used-attempt chunk counts imply 43 parse retries/80 pairs: **$0–$0.01548/PR output-only ceiling for that subset** if none to all become avoidable; superseded-attempt retry savings excluded | Default strict; shape validation remains. Salvage acceptance **not measured**, and saved attempt records lack raw replies. Obtain an authorized dev-only raw-response export first; shared cache includes held-out replies and must not be scanned (`comms/devin-to-claude-1.answer.md`, Q2; `post-freeze-fixes.md:10`) |
| Fresh reasoning-off retry only after `finish_reason=length` | Each 1k avoided completion tokens saves $0.0009/retry, plus $0.0003 per 1k avoided appended input. Output ceiling ≤same $0.01548/PR for the 43-retry subset; eligible subset and actual delta **not measured** | Existing `retryOnLength=fresh`; changes second generation and can alter findings. Compare length-only retries with retained metadata before adoption (`post-freeze-fixes.md:9`; `review.ts:236–238`) |

Parser and fresh-retry estimates overlap and **must not be added**. `cacheTruncated=false` is a reliability option, not a cost cut: refusing cached truncations may spend more (`post-freeze-fixes.md:11`). Verifier removal would avoid its actual cost but is not recommended for adoption: 3.5 verifier-on/off intervals span zero and precision falls when bypassed (`levers-v2.md:34–50`). A lower reasoning-budget parameter is not a supported cut: Token Factory ignored it in decision 070 (`docs/decisions.md:3459–3460`).
